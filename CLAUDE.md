# Consuls — notes for Claude

Desktop dashboard (Tauri 2 + React) for coding agents in tmux on the user's tailnet. See README.md.

## Layout

- `crates/chm-core/` — all remote logic, **no Tauri dependency** (it must stay reusable for a
  future iOS app / always-on push daemon). Entry point: `hub::Core`; UI output via the `Sink` trait.
  - `ssh/` russh connection, auth chain (none → agent → key files), host keys, `exec::run`.
  - `tmux/` control-mode parser, client, quoting, formats, seeding.
  - `hub/` host actors (`host.rs`), per-host tmux state (`tmux_mgr.rs`), attention engine.
  - `integration/` hook assets upload, events.jsonl tail, opt-in global install.
- `src-tauri/` — thin shell: commands, frame batching, alerts (rodio chimes, WinRT toasts), tray.
- `src/` — React UI. `ipc/bindings/` is generated by ts-rs (`cargo test -p chm-core`); don't edit.
- `remote-assets/` — files uploaded to `~/.local/share/consuls/` on hosts (placeholders
  `__HOOK__`, `__TMUX__` are filled in at upload; content hash = version).

## Rules

- **Never type into, resize, or kill the user's real tmux sessions when testing.** Use a
  private socket: `CHM_TMUX_SOCKET=<name>` for the whole core, `tmux -L chm-test-…` in tests,
  or `cargo run -p chm-core --example selftest`. Attaching read-only to real sessions is fine.
- Don't install the global integration (edits the user's Claude/Codex/omp configs) yourself.
- Ask before committing. The branch is `master`.

## tmux gotchas (all verified on tmux 3.4)

- A command line with a parse error returns **one** `%error` for the whole line; a runtime
  error aborts the rest of the line. The client completes a pending entry on the first error.
- Unquoted `%0:off` is a syntax error; `quote()` never leaves `%` or `:` bare.
- `set-option -t '=name'` fails ("no such session: =name"); use plain names we generated.
- `-F` output replaces control chars (even tabs) with `_` for non-tty clients → fields are
  separated by `|~|` (`formats::SEP`).
- `capture-pane -S -N -E -1` with no history returns visible line 0 → check `history_size`.
- Control clients get `%output` only for windows in their session; grouped sessions share
  windows, so attach one client per `session_group`.
- Claude Code only runs hooks in folders it trusts (the trust prompt blocks them).

## Direct panes (no tmux)

- `PaneInfo.kind` is `tmux` or `direct`; tmux-only fields live in `PaneInfo.tmux`. Use
  `lib/panes.ts` (`paneIdentity`, `paneWhere`, `paneName`) instead of reaching into `tmux`.
- The core answers terminal queries for direct panes (`term::Collector` → `PtyWrite`), so the
  expanded xterm must not: `TerminalView` swallows DA/DSR/DECRQM/OSC-colour queries when `raw`.
- Hooks route by `CHM_PANE=direct:<chm_id>` (set when the shell starts); `chm-hook.sh` prefers
  `$TMUX_PANE`, so tmux started inside a direct shell still routes to the tmux pane.
- Direct panes outlive their connection: they sit in `Ctx::direct`, not in a host actor.
- This PC is host `@local` (`local.rs`): not in `config.hosts`, always connected. Paths shown to
  the UI use forward slashes (`C:/Users/…`), but programs/cwds go to CreateProcess with native
  backslashes — cmd.exe parses `C:/WINDOWS/…` in its own command line as `/W` switches.
- ConPTY asks for the cursor position (`ESC[6n`) at startup and waits; the core's answer is
  what lets local shells start even when no view is open.
- Local hooks run through Git for Windows' `sh.exe`; `CHM_STATE_DIR` tells `chm-hook.sh` where
  the events file is (the core polls it). Templates use `__RUN__`/`__SH__` placeholders.

## Testing

- Core end-to-end: `cargo run -p chm-core --example selftest -- <host> <user>` (private tmux
  socket; covers sizing, labels, direct shells, reconnect, hooks).
- This PC shells: `cargo run -p chm-core --example localtest` (every local shell: typing,
  resize, hook routing, exit → ended, dismiss).
- Real UI end-to-end: start the app with
  `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333`, then
  `HOST=<host> node scripts/e2e/cdp.mjs scripts/e2e/direct-shell.mjs` (or `local-shell.mjs`,
  `SHELL_NAME="Git Bash"` to pick a shell). The driver evaluates JS in
  the WebView and sends real key events; keep tests on direct shells or private sockets.

## Windows dev gotchas

- Git Bash rewrites `/tmp`-style args into Windows paths; prefix with `MSYS_NO_PATHCONV=1`.
- Shell heredocs mangle backslash escapes in inline Python; write helper scripts to the
  scratchpad with the Write tool and run them.
- The debug app locks `target/debug/consuls.exe`; `taskkill //IM consuls.exe //F` before rebuilding.
